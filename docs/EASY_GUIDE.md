## 1. 한 문장 요약

**"비행기 엔진의 센서 기록을 보고, 이 엔진이 고장까지 몇 번 더 운행할 수 있는지 AI로 맞히는 프로젝트"** 입니다.

- 이 "고장까지 남은 운행 횟수"를 **잔존수명(RUL, Remaining Useful Life)** 이라고 부릅니다.
- 과제의 필수 항목은 그중 더 단순한 질문인 **"지금 고장 임박(남은 횟수 30번 이하) 상태인가?"를 예/아니오로 맞히기**이고,
  우리는 여기에 더해 "정확히 몇 번 남았는가"까지 맞혔습니다.
- 결과는 웹 대시보드에서 엔진별 신호등(빨강·노랑·초록)으로 보여줍니다.

## 2. 왜 이런 걸 하나요? (자주 나오는 질문)

### Q. 제조사가 "이 엔진 수명은 200번"이라고 하면, 그냥 200에서 빼면 되지 않나요?

안 됩니다. **같은 모델의 엔진이라도 실제 수명이 제각각**이기 때문입니다.
우리 데이터의 엔진 100대도 전부 같은 모델인데, 가장 빨리 고장 난 엔진은 **128번**,
가장 오래 버틴 엔진은 **362번** 운행하고 고장 났습니다 (평균 약 206번).

- "평균 206번이니까 지금 100번 돌았으면 106번 남았다"라고 계산하면,
  128번에 고장 날 엔진한테는 **이미 고장 난 뒤에도 "아직 한참 남았다"** 고 말하게 됩니다 → 위험
- 반대로 362번까지 버틸 엔진은 **멀쩡한데 너무 일찍 교체**하게 됩니다 → 낭비

그래서 **엔진마다 실제로 얼마나 닳았는지를 센서로 보고 따로 추정**하는 것이 이 프로젝트의 핵심입니다.
실제로 "평균에서 빼기" 방식(베이스라인)보다 우리 AI 모델이 오차를 **61% 줄였습니다** (5장 참고).

### Q. 이상이 감지되면 그냥 바로 정비하면 되지, 왜 남은 수명까지 계산하나요?

"이상 있음/없음"만으로는 **얼마나 급한지**를 알 수 없기 때문입니다.

| | 이상탐지만 있을 때 | 잔존수명(RUL)까지 있을 때 |
|---|---|---|
| 알려주는 것 | "지금 문제 있음" | "앞으로 약 15번 운행하면 고장" |
| 엔진 10대에 동시에 경고가 뜨면 | 무엇부터 고칠지 모름 | 남은 횟수가 적은 순서대로 정비 |
| 정비 준비 | 경고가 뜨면 급하게 정지 | 부품 주문·인력 배치를 **미리 계획** |

휴대폰 배터리의 "남은 시간 3시간" 표시와 비슷합니다. 값은 계속 바뀌지만,
"20% 밑으로 떨어지면 충전"이라는 규칙은 잘 작동하죠. 우리도 **"남은 수명이 30번 이하면 빨간불"** 같은 규칙으로 씁니다.

## 3. 데이터 이해하기

### 어떤 데이터인가요?
- **NASA C-MAPSS FD001**: NASA가 만든 **터보팬 엔진(비행기 제트엔진) 고장 시뮬레이션 데이터**입니다.
  실제 비행기에서 뽑은 값이 아니라 컴퓨터로 정교하게 만든 값이라는 점은 발표 때 꼭 밝혀야 합니다.
- "FD001"은 4개 버전 중 가장 단순한 버전입니다: 운전 조건 1가지, 고장 원인 1가지(압축기 손상).

### 데이터 파일 3개 (`data/` 폴더)

| 파일 | 내용 | 쉽게 말하면 |
|---|---|---|
| `train_FD001.txt` | 엔진 100대가 **처음부터 고장 날 때까지** 모든 기록 (약 2만 줄) | 공부용 문제집 (정답 포함) |
| `test_FD001.txt` | 다른 엔진 100대의 **고장 나기 전 중간까지만** 기록 | 시험지 (정답 없음) |
| `RUL_FD001.txt` | test 엔진 100대의 실제 남은 수명 | 시험 정답지 |

### 한 줄에 들어 있는 정보
- **엔진 번호**: 몇 번 엔진인지 (1~100)
- **사이클(cycle)**: 그 엔진의 **몇 번째 운행**인지. 1번 비행 = 1사이클이라고 생각하면 됩니다.
  이 프로젝트의 "시간" 단위이고, 수명도 전부 사이클로 셉니다.
- **운전 설정 3개**: 고도·속도 같은 비행 조건
- **센서 21개**: 온도, 압력, 회전 속도 등 엔진에 달린 계측기 값

### 중요한 센서 (모델이 가장 많이 참고한 것)
| 센서 | 의미 | 왜 중요한가 |
|---|---|---|
| s4 | 저압 터빈 출구 온도 | 엔진이 닳을수록 **점점 뜨거워짐** — 모델이 가장 많이 참고 (중요도 58%) |
| s9 | 엔진 코어 회전 속도 | 열화가 진행되면 회전 패턴이 달라짐 |
| s3 | 고압 압축기 출구 온도 | 고장 원인(압축기 손상)과 직접 연결됨 |

21개 센서 중 **10개는 값이 거의 변하지 않아서** 버리고 14개만 씁니다.
(움직이지 않는 센서는 "닳았는지" 알려주는 정보가 없기 때문입니다.)

## 5. 단계별로 무슨 일을 하나요?

### ① 정답(라벨) 만들기 — "남은 수명"을 어떻게 알까?
train 데이터는 엔진이 고장 날 때까지 기록돼 있어서, 거꾸로 세면 정답을 알 수 있습니다.

> 예) 200번째 운행에서 고장 난 엔진이라면
> 150번째 운행 시점의 남은 수명 = 200 − 150 = **50**

**그런데 한 가지 손질을 합니다 — "125에서 자르기"**
- 새 엔진은 1번째 운행이든 30번째 운행이든 센서 값이 똑같이 "건강"합니다.
  그런데 정답은 300, 270처럼 다르면, 모델이 구분할 수 없는 걸 억지로 맞히려다 헷갈립니다.
- 그래서 **남은 수명이 125보다 크면 전부 125로 통일**합니다. 뜻은 "아직 한참 남음"입니다.
- 모델은 **정말 중요한 구간(고장이 다가오는 125번 이내)** 을 집중해서 배우게 됩니다.
- 왜 하필 125? 가장 빨리 고장 난 엔진의 수명이 128이라, 그보다 조금 작은 값을 골랐습니다.
  (다른 연구들도 많이 쓰는 값이라 결과 비교도 쉽습니다.)

### ② 센서 값 맞추기 (정규화)
센서마다 숫자 크기가 완전히 다릅니다 (어떤 건 9,000대, 어떤 건 0.0x). 그대로 넣으면 **숫자가 큰 센서가
괜히 중요해 보이는** 문제가 생겨서, 모든 센서를 "평균 0, 퍼진 정도 1"로 맞춰 줍니다.
시험 과목마다 만점이 다를 때 점수를 **표준점수로 바꾸는 것**과 같은 원리입니다.

> ⚠️ 이때 평균·퍼진 정도는 **공부용 데이터(train)로만** 계산합니다. 시험 데이터까지 보고 계산하면
> "시험 문제를 미리 본 것"이 되어 점수가 부풀려집니다. 이를 **데이터 누수**라고 부릅니다.

### ③ 공부용·연습용 나누기
train 엔진 100대를 **80대(공부용)** 와 **20대(연습 시험용 = 검증용, validation)** 로 나눕니다.
- 엔진을 **통째로** 나눕니다. 한 엔진의 앞부분은 공부용, 뒷부분은 연습용으로 쪼개면
  "이미 본 엔진의 미래를 맞히는" 셈이라 실력이 부풀려지기 때문입니다.
- 연습 시험 점수로 설정값을 고르고, 마지막에 **진짜 시험(test 100대)** 으로 최종 점수를 냅니다.

### ④ 기준 모델 (베이스라인) — "센서를 안 보면 이 정도"
- 방법: **train 엔진들의 평균 수명 − 지금까지 운행한 횟수**
- 센서를 전혀 보지 않습니다. AI 모델이 이걸 이겨야 "센서를 본 의미가 있다"고 말할 수 있습니다.

### ⑤ 모델 1: 랜덤포레스트 (Random Forest)
- **간단한 질문 여러 개로 답을 좁혀가는 "스무고개 나무"를 수백 개 만들어, 그 답을 평균 내는 방법**입니다.
  (예: "s4 온도가 1,420보다 높은가?" → "최근 15번 동안 온도가 오르고 있는가?" → …)
- 이 모델은 "지금 이 순간 값"만 보기 때문에, **최근 15번 운행 동안의 평균·흔들림·기울기(오르는지 내리는지)** 를
  따로 계산해서 같이 넣어 줍니다. 이걸 **롤링 윈도우(이동 구간)** 라고 합니다.
- 나무 개수 등 설정은 감으로 정하지 않고 **후보 4개를 실제로 돌려서 연습 시험 점수가 가장 좋은 것**을 골랐습니다.

### ⑥ 모델 2: LSTM (최종 채택)
- **순서가 있는 데이터(시간 흐름)를 처음부터 차례대로 읽으면서 기억해 두는 인공신경망**입니다.
  책을 한 쪽씩 읽으며 앞 내용을 기억하는 것처럼, 1번 운행부터 지금까지의 센서 흐름 전체를 봅니다.
- 그래서 랜덤포레스트처럼 "최근 15번 평균" 같은 걸 따로 만들어 줄 필요가 없습니다.
- 구조와 설정은 MathWorks(MATLAB 회사)의 공식 예제를 그대로 따랐습니다. 참고한 자료와
  바꾼 부분은 `DESIGN_DECISIONS.md`에 적혀 있습니다.

### ⑦ 과제 필수: 고장 임박 이진 분류 (09번)
"남은 수명이 몇 번인가?"(숫자) 대신 **"지금 위험한가, 아닌가?"(예/아니오)** 를 맞히는 문제입니다.

- **위험의 정의**: 남은 수명이 **30번 이하**면 "위험(1)", 그보다 많으면 "정상(0)" (문제정의서에 적은 기준)
- **기준 모델 — 이동 Z-score 건강지표**:
  각 센서가 "새 엔진일 때(처음 30번 운행)"보다 얼마나 벗어났는지를 표준점수(Z-score)로 재서 평균 낸 값입니다.
  건강검진 수치가 정상 범위에서 멀어질수록 위험한 것과 같은 원리입니다. 이 값이 일정 기준(1.82)을 넘으면 "위험".
- **머신러닝 모델 — 랜덤포레스트 분류**: ⑤의 스무고개 나무를 "숫자" 대신 "위험/정상"을 맞히도록 학습시킨 것.
  결과가 "위험할 확률 0~1"로 나옵니다.
- **경보 기준(확률 임곗값)을 0.5 → 0.4로 낮춘 이유**: 위험한 엔진을 놓치는 것(미탐)은 고장·긴급 수리로 이어져,
  괜히 점검하는 것(오탐)보다 비용이 약 48배 큽니다. 그래서 **조금 더 일찍, 조금 더 자주** 경보를 울리도록 기준을 낮췄습니다.

## 6. 결과 읽는 법

### [필수 과제] 위험 분류 점수표
연습 시험(검증용 엔진 20대)의 **모든 운행 시점**에서 "위험/정상"을 맞힌 결과입니다.

| 방법 | 정밀도 (Precision) | 재현율 (Recall) | F1 |
|---|---|---|---|
| 기준 모델 (이동 Z-score) | 0.86 | 0.83 | 0.85 |
| **랜덤포레스트 분류 (경보 기준 0.4, 최종)** | 0.89 | **0.90** | **0.90** |
| (참고) LSTM이 예측한 남은 수명 ≤ 30 | 0.91 | 0.94 | 0.92 |

- **정밀도**: "위험하다"고 경보한 것 중 진짜 위험했던 비율 → 낮으면 **괜한 점검**이 많음
- **재현율**: 진짜 위험했던 것 중 경보로 잡아낸 비율 → 낮으면 **위험을 놓침** (더 중요)
- **F1**: 두 값을 합친 종합 점수. 셋 다 1에 가까울수록 좋습니다.
- **정확도(accuracy)는 일부러 안 씁니다.** 위험한 시점은 전체의 16%뿐이라, 무조건 "정상"이라고만 해도 정확도가 84%가 나와서 착시를 일으키기 때문입니다.
- 첫 경보는 실제 고장 **약 30번 운행 전**(중앙값)에 울렸습니다. 목표로 한 30번과 거의 같습니다.

**틀린 사례 두 가지** (그림: `outputs/figures/cls_error_case_false_alarm.png`, `cls_error_case_missed.png`)
- **오탐 (엔진 #22)**: 실제로는 31~53번 남았는데 "위험"이라고 경보. 이 엔진은 다른 엔진들보다 **온도가 일찍 많이 올라서**
  이미 위험한 엔진처럼 보였습니다. 다만 고장보다 조금 이른 점검이라 손해는 작습니다.
- **미탐 (엔진 #93)**: 실제로는 30번 이하로 남았는데 한동안 경보가 없다가, 19번 남았을 때에야 경보. 이 엔진은
  **온도가 덜 오른 상태에서 고장**나는 개체라 모델이 늦게 알아챘습니다.

### [선택 과제] 남은 수명 점수표 (시험용 test 엔진 100대 기준)

| 방법 | 평균 오차 (MAE) | RMSE | NASA 점수 |
|---|---|---|---|
| 기준 모델 (평균 수명 − 운행 횟수) | 28.1번 | 36.6 | 22,964 |
| 랜덤포레스트 | 14.2번 | 19.9 | 1,276 |
| **LSTM (최종)** | **10.8번** | **14.8** | **288** |

세 점수 모두 **낮을수록 좋습니다.**

- **MAE (평균 오차)**: 평균적으로 몇 번 틀렸는지. "LSTM은 보통 **11번 운행 정도** 차이로 맞힌다"는 뜻입니다.
- **RMSE**: MAE와 비슷한데, **크게 틀린 경우에 벌점을 더 크게** 줍니다. MAE보다 크면 가끔 크게 틀리는 경우가 있다는 뜻입니다.
- **NASA 점수**: 이 데이터를 만든 NASA의 공식 채점 방식입니다.
  **"실제보다 늦게 경고하는 것"(아직 남았다고 했는데 먼저 고장)에 훨씬 큰 벌점**을 줍니다.
  현장에서는 늦은 경고가 사고로 이어지기 때문입니다. 기준 모델 22,964 → LSTM 288로 크게 줄었다는 것은
  **위험하게 틀리는 경우가 확 줄었다**는 뜻입니다.

### 모델이 틀린 두 가지 방향

| 종류 | 뜻 | 결과 | 우리 사례 |
|---|---|---|---|
| **위험한 오류** (과대예측) | 실제보다 **많이 남았다고** 예측 | 정비 시점을 놓쳐 **고장·사고** 위험 | 엔진 #79: 실제 63번 남음 → 약 92번으로 예측 |
| **보수적 오류** (과소예측) | 실제보다 **적게 남았다고** 예측 | 너무 일찍 정비해서 **비용 낭비** | 엔진 #12: 실제 124번 남음 → 약 81번으로 예측 |

두 방향 중 **위험한 오류가 훨씬 더 나쁩니다.** 그래서 NASA 점수도 이쪽에 벌점을 크게 줍니다.
관련 그림: `outputs/figures/error_case_danger.png`, `error_case_conservative.png`

### "모델이 진짜로 엔진 상태를 보고 판단했나?" 확인
- 모델이 많이 참고한 센서 상위 8개 중 **5개**가, 모델과 무관하게 "시간이 갈수록 꾸준히 변하는 센서"로
  따로 뽑은 목록과 겹쳤습니다.
- 즉 모델이 우연한 잡음이 아니라 **실제로 닳아가는 신호**를 보고 판단했다는 근거입니다.

## 7. 대시보드에서 보이는 것들

| 화면 요소 | 뜻 |
|---|---|
| **신호등 (위험도 등급)** | 🔴 남은 수명 30번 이하 = 지금 바로 정비 일정 잡기 (과제의 "위험" 기준과 같음) / 🟡 30~60번 = 정비 준비 / 🟢 60번 이상 = 여유 |
| **헬스 점수 (0~100)** | 예측 남은 수명을 125 기준 백분율로 바꾼 값. 125 이상 남았으면 100점 |
| **90% 구간** | "실제 남은 수명은 거의(90%) 이 범위 안에 있다". 예) 약 15.2번, 90% 구간 2~29번 |
| **생존곡선** | "앞으로 x번 더 운행해도 아직 고장 나지 않을 확률"을 그린 곡선. 예측값 근처에서 50%를 지나감 |
| **조기경보 성능** | 대시보드 신호등의 "30번 이하면 위험" 규칙이 test 엔진에서 실제로 얼마나 맞았는지 (아래 참고) |
| **비용 시뮬레이션** | 고장 난 뒤 고치는 방식 vs 미리 예측해서 고치는 방식의 비용 비교 |

### 조기경보 성능 읽는 법
test 엔진 100대의 마지막 관측 시점 중 실제로 위험(남은 수명 30 이하)했던 엔진은 25대였습니다.

- **맞게 경고 (TP)**: 24대 — 위험한 엔진을 잘 잡아냄
- **놓침 (FN)**: 1대 — 위험했는데 경고를 못 함
- **괜한 경고 (FP)**: 1대 — 괜찮았는데 경고함

| 지표 | 값 | 뜻 |
|---|---|---|
| 정밀도 (Precision) | 0.96 | 경고한 것 중 진짜 위험했던 비율 (25건 중 24건) |
| 재현율 (Recall) | 0.96 | 진짜 위험했던 것 중 잡아낸 비율 (25대 중 24대) |
| F1 | 0.96 | 위 두 값을 합친 종합 점수 |

※ 이 점수는 엔진마다 **마지막 한 시점**만 본 것이라 표본이 적습니다(100개). 모든 운행 시점을 본
더 엄격한 평가는 6장의 "위험 분류 점수표"(검증용 엔진 20대)를 참고하세요.

### 비용 시뮬레이션은 주의해서 보기
C-MAPSS 데이터에는 **돈이나 정비 시간 정보가 전혀 없습니다.** 그래서 금액과 시간은 **설명을 위한 가정값**이고,
탐지·놓침·괜한 경고 건수만 실제 모델 결과입니다. 발표 때 이 점을 꼭 밝혀야 합니다.

## 8. 용어 사전 (가나다·알파벳 순)

| 용어 | 쉬운 설명 |
|---|---|
| **검증셋 (validation)** | 공부용 데이터에서 떼어 놓은 연습 시험 문제. 설정값을 고를 때 사용 |
| **과대예측 / 과소예측** | 실제보다 크게 / 작게 예측한 것. 남은 수명에서는 과대예측이 더 위험 |
| **기준 모델 (베이스라인)** | 가장 단순한 비교 대상. AI가 이것보다 나아야 의미가 있음 |
| **데이터 누수** | 모델이 보면 안 되는 정보(시험 정답 등)를 학습 중에 보게 되는 실수. 점수가 가짜로 좋아짐 |
| **랜덤포레스트** | 스무고개 나무 수백 개의 답을 평균 내는 모델 |
| **롤링 윈도우** | "최근 N번" 구간의 평균·흔들림·기울기를 계산하는 방법. 우리는 최근 15번 |
| **미탐 / 오탐** | 미탐 = 위험한데 놓친 것(더 위험), 오탐 = 괜찮은데 경보한 것(비용 낭비) |
| **부트스트랩** | 데이터를 여러 번 다시 뽑아 계산해 보면서 결과가 얼마나 흔들리는지 확인하는 방법 |
| **사이클 (cycle)** | 엔진의 운행 1회. 이 프로젝트의 시간 단위 |
| **센서 중요도** | 모델이 판단할 때 각 센서를 얼마나 참고했는지 |
| **시드 (seed=42)** | 무작위 작업을 매번 똑같이 재현하기 위한 번호. 42 자체에 의미는 없음 |
| **이동 Z-score** | 정상일 때 대비 몇 표준편차 벗어났는지를 최근 몇 번 평균으로 부드럽게 본 값. 과제의 기준 모델 |
| **이진 분류** | 답이 두 가지(위험/정상) 중 하나인 문제. 우리 과제의 필수 항목 |
| **임곗값 (threshold)** | "이 값을 넘으면 경보" 하는 기준선 |
| **재현율 / 정밀도 / F1** | 위험을 얼마나 잘 잡는지 / 경보가 얼마나 믿을 만한지 / 둘의 종합 점수 |
| **정규화** | 센서마다 다른 숫자 크기를 같은 기준으로 맞추는 것 (표준점수와 같음) |
| **클리핑 (125)** | 남은 수명이 125보다 크면 125로 자르는 손질. "아직 한참 남음"이라는 뜻 |
| **하이퍼파라미터** | 모델 학습 전에 사람이 정해 주는 설정값 (나무 개수, 학습 횟수 등) |
| **LSTM** | 시간 순서대로 읽으며 앞 내용을 기억하는 인공신경망 |
| **MAE / RMSE** | 평균적으로 얼마나 틀렸는지 보는 점수. 낮을수록 좋음 |
| **NASA 점수** | 늦은 경고에 더 큰 벌점을 주는 공식 채점 방식. 낮을수록 좋음 |
| **RUL (잔존수명)** | 고장까지 남은 운행 횟수. 이 프로젝트의 예측 대상 |
| **test / train** | 시험용 데이터 / 공부용 데이터 |
