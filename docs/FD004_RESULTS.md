# FD004 실험 결과 — "더 어려운 데이터에서도 되는가?"

## 1. FD004는 무엇이 더 어려운가

| | FD001 | FD004 |
|---|---|---|
| 운전조건 (비행 조건 조합) | 1개 | **6개** — 고도 0~42천 ft, 마하 0~0.84, 스로틀 60/100 |
| 고장 모드 | 1개 (고압압축기 손상) | **2개** (고압압축기 + 팬 손상) |
| train / test 엔진 | 100 / 100 | 249 / 248 |
| train 수명 (최소·평균·최대) | 128 · 206 · 362 | 128 · 246 · **543** |
| 사용 센서 | 14개 | 15개 (s6 바이패스 덕트 압력이 추가로 살아남음) |

**가장 큰 차이 — 운전조건이 계속 바뀜.** 같은 엔진이 한 사이클은 고도 0, 다음 사이클은 고도 42천 ft로
운항해서 센서값이 사이클마다 크게 뜁니다 (예: 엔진 #179의 s4 온도가 연속한 사이클에서 1,045 → 1,300 → 1,114°R).
이 차이를 빼지 않으면 "비행 조건이 바뀐 것"이 "엔진이 닳은 것"처럼 보입니다.

## 2. 무엇을 바꿨나 (FD004 대응)

코드는 FD001과 **같은 파이프라인**이고, 데이터셋 이름(`CMAPSS_DATASET`)만 바꿔 실행합니다.
다중 운전조건 대응으로 `common.py`에 세 가지를 추가했습니다 (근거: `DESIGN_DECISIONS.md` 임의 설정값 #13).

1. **운전조건 구분**: 운전 설정 3개를 반올림한 조합으로 6개 운전조건을 나눔 (`assign_regime`)
2. **운전조건별 정규화**: 센서마다 "그 운전조건의 train 평균·표준편차"로 Z-score (`Normalizer`)
   — 조건 차이는 사라지고 열화 신호만 남음. MathWorks similarity-based RUL 참고자료의 방식과 같은 아이디어
3. **운전조건 보정값**: 그래프·추세 분석용으로 "원래값 − 조건 평균 + 전체 평균" (단위는 유지, `RegimeCorrector`)

FD001은 운전조건이 하나라 세 가지 모두 예전 계산과 같습니다 (다시 실행해서 결과가 같은 것을 확인 — 차이는 소수점 넷째 자리 이하).

## 3. 결과 — 필수 과제: 고장 임박 이진 분류 (위험 = 잔여 ≤ 30)

| 방법 | FD001 validation F1 | **FD004 validation F1** | FD004 Precision | FD004 Recall | FD004 공식 test F1 |
|---|---|---|---|---|---|
| 기준 모델 (이동 Z-score) | 0.849 | **0.551** | 0.521 | 0.585 | 0.449 |
| RandomForest 분류 (임곗값 0.40, 최종) | 0.895 | **0.864** | 0.860 | 0.868 | 0.881 |
| (선택) LSTM 회귀 → 예측 RUL ≤ 30 | 0.923 | **0.876** | 0.923 | 0.834 | 0.914 |

(FD004 validation = 49대의 모든 사이클, 공식 test = 248대의 마지막 관측 시점 — 위험 엔진 53대)

- **단순한 기준 모델은 FD004에서 크게 무너집니다** (F1 0.85 → 0.55). 고장 모드가 2개라 센서마다 열화 방향이
  엔진에 따라 다르고, 여러 센서를 단순 평균하는 건강지표로는 구분이 어렵습니다.
- **머신러닝 모델은 성능을 대부분 지켰습니다** (RandomForest 0.90 → 0.86). "Z-score 기준 모델 대비 ML의 가치"가
  FD001보다 FD004에서 훨씬 뚜렷하게 드러납니다 — 발표에서 쓰기 좋은 포인트입니다.
- 확률 임곗값은 FD001과 같은 규칙(train 교차검증에서 Recall ≥ 0.9 중 Precision 최대)으로 다시 골랐고, 결과도 **0.40**으로 같았습니다.
- 첫 경보(3사이클 연속)는 고장 **26사이클 전(중앙값)**, FD001(30사이클 전)보다 조금 늦습니다.
- 위험 기준을 20/30/50으로 바꿔도 RandomForest F1은 0.848~0.855로 안정적입니다.

## 4. 결과 — 선택 과제: 잔존수명(RUL) 회귀 (공식 test, 엔진별 마지막 시점)

| 모델 | FD001 MAE | **FD004 MAE** | FD004 RMSE | FD004 NASA score |
|---|---|---|---|---|
| 베이스라인 (평균 수명 − 현재 사이클) | 28.08 | **47.42** | 59.01 | 3,063,392 |
| Random Forest | 14.19 | **21.81** | 29.07 | 7,139 |
| **LSTM** | 10.85 | **18.70** | 25.84 | 4,281 |

- LSTM이 베이스라인 대비 MAE를 **60.6%** 줄였습니다 (FD001은 61.4%) — 데이터가 어려워져도 개선 폭은 거의 같습니다.
- 오차의 절대 크기는 FD001보다 약 1.7배 큽니다. 수명 범위가 훨씬 넓고(최대 543사이클) 고장 모드가 섞여 있기 때문입니다.
- 공개 연구들에서 FD004의 LSTM 계열 RMSE가 대체로 20대 중후반으로 보고되는데, 우리 결과(25.84)도 그 범위입니다.
- 학습 시간: RF 약 8분, LSTM 약 14.5분 (CPU 기준, FD001의 약 3~4배).

## 5. 모델이 본 센서가 달라졌다

| 순위 | FD001 | FD004 |
|---|---|---|
| 1 | s4 · T50 저압터빈 출구 온도 (0.58) | **s3 · T30 고압압축기 출구 온도 (0.50)** |
| 2 | s9 · Nc 코어 속도 (0.09) | **s17 · htBleed 블리드 엔탈피 (0.14)** |
| 3 | s3 · T30 고압압축기 출구 온도 (0.06) | **s8 · Nf 팬 속도 (0.11)** |

FD004에는 **팬 손상** 고장 모드가 추가되어, 팬 속도(s8)처럼 FD001에서는 중요하지 않던 팬 계통 신호가 상위에
올라왔습니다. RF 중요도 상위 8개 중 5개가 추세성 상위 8개와 겹쳐(s8, s11, s13, s14, s17), FD001처럼
"모델이 실제 열화 신호를 보고 판단했다"는 근거도 유지됩니다. 그림: `outputs/FD004/figures/feature_importance_top8.png`

## 6. 오탐·미탐 사례 (`outputs/FD004/figures/cls_error_case_*.png`)

**오탐 — 엔진 #179 (수명 435사이클, 오탐 35사이클)** — FD004에서 새로 보인 유형
- 실제 잔여 194~223사이클 시점(운행 212~241번째)에 위험 경보가 울렸습니다.
- 원인을 원본 데이터에서 확인해 보니, 이 엔진은 운행 241번째 전후로 **모든 센서가 한꺼번에 정상 수준으로 되돌아갑니다**
  (같은 운전조건끼리 비교해도 s4가 1,139 → 1,112°R로 떨어짐). 중간에 정비를 받은 것 같은 모양입니다.
  되돌아가기 직전까지는 온도·압력이 실제로 위험 엔진 수준까지 올라가 있었으므로, 모델 입장에서는 경보가 합리적이었습니다.
- 이런 "중간에 되돌아가는" 엔진이 train에 3대(#71, #179, #185) 있습니다. 실제 현장이라면 **정비 이력 데이터**가 있어야
  "정비 후 초기화"를 알 수 있다는 점 — 데이터의 한계로 보고서에 쓸 만한 사례입니다.
- 나머지 오탐 7사이클은 잔여 31~39 — 위험 기준 직전의 "조금 이른 경보"입니다.

**미탐 — 엔진 #105 (수명 170사이클, 미탐 16사이클)** — FD001 #93과 같은 유형
- 잔여 30~15 구간에서 경보가 없다가 잔여 15에서야 위험 확률이 0.4를 넘었습니다.
- 위험 구간에 들어설 때 s3(고압압축기 출구 온도) 15사이클 평균이 약 1,422°R로, 다른 엔진들이 위험에 들어설 때 평균
  (1,424.2°R)보다 **낮았습니다.** 낮은 온도 수준에서 고장에 이르는 개체라 모델이 늦게 알아챈 것입니다.

## 7. 결론과 제안

- **"더 어려운 데이터에서도 된다"**: 운전조건별 정규화만 추가하면 같은 파이프라인이 FD004에서도 작동하고,
  ML 모델의 성능 하락은 작습니다 (분류 F1 0.90 → 0.86, 회귀 개선율 61% → 61%).
- **기준 모델 대비 ML의 가치가 더 커짐**: 기준 모델은 F1 0.55로 무너지지만 RandomForest는 0.86 — 발표의
  "왜 머신러닝이 필요한가"를 설명하기에 FD001보다 설득력 있는 근거입니다.
- **제안**: 발표 본편은 FD001로 가고, FD004는 "확장 실험" 한 장으로 "더 현실적인(조건이 계속 바뀌는) 데이터에서도
  검증했다"를 보여주는 구성을 추천합니다. 대시보드(08번)는 FD001 전용으로 두었습니다.
