> 최종 수정: 2026-09-30 (FD004 중심 재구성, 위험 기준 30 → 40 통일, 최종 회귀 모델 LSTM → GRU 교체)
> 우리 프로젝트의 **주 데이터는 FD004**이고, FD001은 같은 코드의 비교 기준입니다.
> 결과 파일: `outputs/FD004/` (주), `outputs/FD001/` (비교), `outputs/cross_dataset/` (교차 검증).

## 1. 왜 FD004인가 — FD001보다 무엇이 어려운가

| | FD001 (비교) | **FD004 (주)** |
|---|---|---|
| 운전조건 (비행 조건 조합) | 1개 | **6개** — 고도 0~42천 ft, 마하 0~0.84, 스로틀 60/100 |
| 고장 모드 | 1개 (고압압축기 손상) | **2개** (고압압축기 + 팬 손상) |
| train / test 엔진 | 100 / 100 | 249 / 248 |
| train 수명 (최소·평균·최대) | 128 · 206 · 362 | 128 · 246 · **543** |
| 사용 센서 | 14개 | 15개 (s6 바이패스 덕트 압력이 추가로 살아남음) |

같은 엔진이 한 사이클은 고도 0, 다음 사이클은 고도 42천 ft로 운항해서 센서값이 사이클마다 크게 뜁니다
(예: 엔진 #179의 s4 온도가 연속한 사이클에서 1,045 → 1,300 → 1,114°R). 실제 현장처럼 조건이 계속 바뀌는
데이터라, "현장에서도 쓸 수 있는가"를 보여주기에 FD001보다 적합합니다.

## 2. 다중 운전조건 대응 (`common.py`, 근거: `DESIGN_DECISIONS.md` #13)

1. **운전조건 구분**: 운전 설정 3개를 반올림한 조합으로 6개 운전조건을 나눔 (`assign_regime`)
2. **운전조건별 정규화**: 센서마다 "그 운전조건의 train 평균·표준편차"로 Z-score (`Normalizer`)
   — 조건 차이는 사라지고 열화 신호만 남음 (MathWorks similarity-based RUL 참고자료와 같은 아이디어)
3. **운전조건 보정값**: 그래프·추세 분석·대시보드 센서 추이용으로 "원래값 − 조건 평균 + 전체 평균" (단위 유지, `RegimeCorrector`)

FD001은 운전조건이 하나라 세 가지 모두 일반 계산과 같습니다(재실행으로 확인).

## 3. 위험 기준 = 잔여 ≤ 40사이클 (분류 라벨·대시보드 빨간불·정비 경보 모두 같은 값)

과제 예시값(30) 대신, C-MAPSS 정비 일정 논문의 운영 조건(정비 준비 7일, 정비 슬롯 10~20일 간격, 주간 계획,
비용 1:5 또는 1:2)으로 "예측 RUL이 N 이하면 경보 → 정비"를 시뮬레이션해 **운행 1사이클당 정비 비용이 가장 낮은 N**을 골랐습니다
(`scripts/13_threshold_cost.py`, 그림 `outputs/FD004/figures/threshold_cost.png`).

| FD004 GRU(최종 모델), 위험 기준 N | 30 | 35 | **40** | 45 | 50 |
|---|---|---|---|---|---|
| 정비 전에 고장 나는 엔진 | 14.3% | 3.2% | **0.2%** | 0% | 0% |
| 비용 (최저 대비, 1:5) | +48% | +9% | **최저** | +2% | +5% |

- 비용 비율 1:5(de Pater 2022)와 1:2(Lee & Mitici 2023) 모두 **최적 N = 40**. 교체 전 모델(LSTM)로 계산해도 40이었음.
- 예전 기준 30은 정비 준비가 끝나기 전에 엔진 7대 중 1대꼴로 고장 → 비용 +48%.
- FD001(비교)은 모델 오차가 작아 최적이 30이지만, 40으로 해도 비용 차이는 3~5% — 두 데이터셋에 같은 기준 40을 씁니다.
- 분류 성능으로 봐도 40~50 구간이 가장 좋음 (FD004 GRU → 분류 F1: 20 0.810 / 30 0.878 / **40 0.915** / 50 0.926 / 60 0.922).

## 4. 필수 과제 — 고장 임박 이진 분류 (`09_classification.py`)

| 방법 | Precision | Recall | **FD004 validation F1** | FD004 test F1 | FD001 validation F1 (비교) |
|---|---|---|---|---|---|
| 기준 모델 (이동 Z-score) | 0.566 | 0.600 | **0.583** | 0.589 | 0.861 |
| RandomForest 분류 (임곗값 0.5) | 0.879 | 0.830 | 0.854 | 0.905 | 0.906 |
| **RandomForest 분류 (임곗값 0.36, 최종)** | 0.841 | 0.887 | **0.863** | **0.915** | 0.894 (임곗값 0.34) |
| (선택) GRU 회귀 → 예측 RUL ≤ 40 | 0.947 | 0.885 | **0.915** | 0.931 | 0.947 |

(FD004 validation = 49대의 모든 사이클 / 공식 test = 248대의 마지막 관측 시점, 그중 위험 엔진 69대)

- **단순한 기준 모델은 FD004에서 크게 무너집니다** (FD001 0.86 → FD004 0.58). 고장 모드가 2개라 센서마다 열화 방향이
  엔진에 따라 다르고, 여러 센서를 단순 평균하는 건강지표로는 구분이 어렵습니다.
- **머신러닝은 성능을 지켰습니다** (RandomForest 0.89 → 0.86). "왜 머신러닝이 필요한가"가 FD004에서 가장 뚜렷하게 드러납니다.
  기준 모델이 놓친 위험 사이클 803개 → RandomForest 227개.
- 공식 test 위험 엔진 69대 중 65대를 잡았고(놓침 4대), 정상 179대 중 8대에 괜한 경보.
- 확률 임곗값 0.36은 train 엔진 5-겹 교차검증에서 "Recall ≥ 0.9 중 Precision 최대"로 고른 값 (DESIGN_DECISIONS #12).
- 첫 경보(3사이클 연속)는 고장 **35사이클 전(중앙값)** — 문헌 운영 조건의 정비 리드타임(평균 17사이클)보다 이릅니다.
  validation 49대 모두 고장 18사이클 이상 전에 첫 경보를 받았습니다. (최댓값 243은 중간 정비로 의심되는 엔진 #179의 이른 경보가 잡힌 값이라 중앙값만 믿으세요.)

### 이 숫자들을 얼마나 믿을 수 있나 (`classification_uncertainty.json`)
점수는 "한 번 나눈 결과"라서 표본이 작을수록 흔들립니다. 두 가지로 확인했습니다.

**① 공식 test의 재현율·정밀도 95% 구간 (Wilson 구간, 위험 엔진 69대)**

| 방법 | 재현율 | 정밀도 |
|---|---|---|
| 기준 모델 (Z-score) | 0.55 (0.43 ~ 0.66) | 0.63 (0.51 ~ 0.74) |
| RandomForest 분류 (0.36) | 0.94 (0.86 ~ 0.98) | 0.89 (0.80 ~ 0.94) |
| GRU 회귀 → 분류 | 0.88 (0.79 ~ 0.94) | 0.98 (0.91 ~ 1.00) |

기준 모델과 머신러닝은 구간이 겹치지 않아 **차이가 확실**합니다. RandomForest와 GRU는 구간이 많이 겹쳐서 **test만으로는 우열을 가릴 수 없습니다.**

**② validation F1의 95% 구간 (엔진 49대를 단위로 2,000번 다시 뽑는 부트스트랩)**

| 방법 | F1 | 95% 구간 |
|---|---|---|
| RandomForest 분류 (0.36) | 0.863 | 0.833 ~ 0.890 |
| GRU 회귀 → 분류 | 0.915 | 0.889 ~ 0.936 |
| 차이 (GRU − RF) | +0.051 | +0.028 ~ +0.074 (2,000번 모두 GRU가 위) |

사이클 단위 표본이 1만 개가 넘어도 같은 엔진의 연속 사이클은 거의 같은 정보라서, 독립 표본은 엔진 49대입니다. 엔진 단위로 보아도 GRU가 조금 낫다는 근거가
있습니다(test의 점수 방향 0.931 대 0.915도 같음). 크기는 F1 약 0.03~0.07이라 "크게 낫다"가 아니라 **"조금 낫다"**가 정확합니다.

**③ 엔진 단위로 보면** 안전한 구간(잔여 40 초과)에서 한 번이라도 경보를 받은 엔진이 49대 중 **RandomForest 25대, GRU 10대**입니다.
사이클 단위 헛경보비율(16% / 5%)이 작아 보여도 엔진 하나하나가 겪는 헛경보는 더 흔합니다 (한 사이클짜리 경보도 센 것이며, 3사이클 연속 규칙을 쓰면 줄어듭니다).

### 6-3. 어떻게 읽나
- **선정 방식 (DESIGN_DECISIONS #14)**: 우선순위(놓침 → 헛경보 → MAE)는 문헌의 비용 비율로 정당화하고, 비교는 정비 비용 시뮬레이션으로 합니다.
  "미탐 15% 이하, 헛경보 20% 이하" 같은 합격선은 근거가 없어 쓰지 않습니다. GRU는 MAE가 후보 중 가장 낮아서, 미탐율 상한을 11.5% 이상·헛경보
  상한을 5.3% 이상 어디에 두어도 GRU가 선정됩니다.
- **정비 비용도 GRU가 가장 낮고** 순서가 MAE 순서와 거의 같아 두 관점이 같은 결론입니다. 다만 모델마다 가장 싼 기준 N이 달라서 40에서만 비교하면
  표 형태 모델에 불리합니다. 각자의 최적 기준에서 비교하면(1:5) GRU 4.47, LSTM 4.57, ExtraTrees 4.78, HistGB 4.79, MLP 4.80, RandomForest 4.82, Ridge 4.87,
  1D-CNN 5.10으로, GRU의 우위는 **약 4~14%**입니다. GRU와 LSTM은 1~2% 차이로 사실상 동률입니다.
- **GRU가 모든 칸에서 1등은 아닙니다.** test에서 놓친 위험 엔진은 MLP가 5대로 가장 적고(대신 헛경보 6대), validation의 오탐율·헛경보비율은 Ridge가 더 낮습니다
  (Ridge는 위험의 40%를 놓침). 미탐율 최저는 validation 기준이고, 경보 지표는 시드 42 한 번의 결과입니다.
- **MAE가 작은 모델일수록 미탐율도 낮음** (상관계수 r = 0.87, MAE 1사이클당 미탐율 약 4%p). 반면 오탐율(r = −0.13)·헛경보비율(r = 0.13)은
  MAE와 거의 무관 — 평균 오차가 작다고 괜한 경보까지 줄지는 않습니다.
- 엔진의 전체 이력을 기억하는 순환 신경망(GRU·LSTM)이 가장 좋고 표 형태 모델들은 서로 비슷합니다. 다만 순환 모델은 전체 이력을, 표 형태 모델은 최근 15사이클
  특성만 입력으로 받아 **입력 정보량이 다르고**, RandomForest 외 후보는 하이퍼파라미터를 조정하지 않았습니다. 우위가 구조 때문인지 입력 때문인지는 가려내지 못했습니다.

## 7. 교차 검증 — 한 데이터로 학습한 모델이 다른 데이터에도 통하나? (`10_cross_dataset.py`)

공식 test 기준, GRU 회귀 MAE (그림 `outputs/cross_dataset/cross_dataset_gru_mae.png`):

| 학습 → 평가 | GRU MAE | 위험 분류 F1 (GRU ≤ 40) |
|---|---|---|
| FD004 → FD004 (기준) | 17.31 | 0.931 |
| **FD004 → FD001** | **11.16** | 1.000 |
| FD001 → FD001 (기준) | 9.63 | 0.964 |
| FD001 → FD004 | 55.83 | 0.000 |

- **FD004로 학습한 모델은 FD001에도 통합니다** (MAE 11.16 — FD001 전용 모델 9.63에 가깝고, FD001 전용 RandomForest 14.19보다 좋음).
  FD004의 6개 운전조건 중 하나가 FD001의 조건과 같고, 고장 모드도 FD001의 것을 포함하기 때문.
- **반대(FD001 → FD004)는 실패** (MAE 55.83, 베이스라인 47.42보다 나쁨). 조건 1개·고장 모드 1개만 본 모델은 처음 보는 조건을 처리하지 못함.
  FD004 기준으로 운전조건 보정을 해 줘도 30.82까지만 개선.
- **반대 방향에서는 GRU가 항상 우세하지는 않습니다.** FD001로 학습해 FD004에 적용하면 RandomForest 회귀가 더 낫습니다
  (원래 기준 그대로 45.80 대 GRU 55.83, 운전조건 보정 시 27.21 대 30.82). 분류도 RandomForest가 F1 0.88, GRU 회귀 → 분류가 0.50입니다.
  FD004 → FD001 방향은 GRU가 더 낫습니다 (11.16 대 RandomForest 16.11).
- 결론: **"어려운 데이터로 학습한 모델이 쉬운 데이터도 커버한다"** — FD004를 주 데이터로 삼은 근거. (교체 전 LSTM에서도 같은 결론: 11.28 / 44.61)

## 10. 한계

- 비용·정비 리드타임은 문헌 가정값 — 실제 값을 알면 13번으로 위험 기준을 다시 정할 것. 논문의 방법을 그대로 재현한 것이 아니라 운영 조건을 가져와 단순화한 시뮬레이션이고,
